# FORMA — анкета первичной квалификации клиентов

## Название

**FORMA — MVP анкеты первичной квалификации клиентов** (практический кейс «от запроса клиента до MVP», выполненный в OpenCode).

Проект представляет собой полный цикл продуктовой разработки: от исходного запроса вымышленного клиента до работающего локального веб-приложения. В комплекте собраны аналитические и рабочие документы, техническое задание на MVP, выполненный MVP и критерии его проверки.

## Пользователи

**Кто заказчик и владелец продукта:**

- **Студия дизайна интерьеров FORMA** — владелец процесса. Это студия полного цикла в среднем ценовом сегменте (профили: квартиры, загородные дома, ремонт, планировка, комплектация). Руководитель студии сформулировал запрос на «красивую анкету с калькулятором, CRM и уведомлениями».

**Кто работает с продуктом:**

1. **Потенциальный клиент** — заполняет пошаговую анкету в браузере: оставляет контакты, описывает объект, задачу, сроки и бюджет.
2. **Менеджер студии** — получает готовую карточку заявки с предварительным статусом и списком причин, копирует её и передаёт в работу.

## Основная функция

Пошаговая анкета **первичной квалификации заявки** до живого диалога с менеджером:

- сбор контактов, параметров объекта, услуги, сроков и бюджета;
- проверка обязательных полей с понятными сообщениями об ошибках;
- по прозрачным бизнес-правилам расчёт **предварительного статуса заявки** из трёх вариантов:
  - *Приоритетная*;
  - *Нужно уточнить*;
  - *Не наш формат*;
- сохранение черновика в браузере и восстановление при повторном визите;
- формирование итоговой карточки обращения для менеджера.

Правила квалификации (BR-01…BR-03) вынесены в отдельный модуль `js/rules.js`, проверяются детерминированно и не раскрываются клиенту.

## Форма результата

Результат работы приложения — **карточка заявки** (обычный текст) на отдельном пост-экране. Она содержит:

- дату создания;
- предварительный статус заявки и перечень причин его присвоения;
- имя и контакт клиента;
- параметры объекта (тип, площадь, локация, готовность к удалённому формату);
- услугу, срок начала ремонта, ориентир бюджета;
- кого принимает решение и комментарий клиента;
- дисклеймер о том, что статус — подсказка, а окончательное решение принимает менеджер.

Карточка копируется в буфер обмена одной кнопкой; при недоступности браузерного Clipboard API включается резервный режим ручного выделения и копирования. Клиент видит только нейтральный экран «Спасибо» — статус и причины видны исключительно менеджеру.

## Функциональность MVP

- 4 шага анкеты + экран проверки ответов и пост-экран;
- условный вопрос «Готовы ли к удалённому формату» — только для объектов вне зоны работы студии;
- валидация полей с ошибками под полем и доступность для скринридера;
- экран «Проверьте ответы» с блоками и кнопками «Изменить»;
- черновик в `localStorage` с плашкой восстановления и кнопкой «Начать заново»;
- предупреждение, если хранилище недоступно (деградация без черновика);
- расчёт статуса по трём группам бизнес-правил;
- карточка заявки для менеджера с копированием и запасным ручным путём.

## Технологии

- **HTML5** — семантическая разметка экранов анкеты;
- **CSS** — визуальные стили, прогресс-бар, состояния полей;
- **vanilla JavaScript (ES5)** — без фреймворков и внешних зависимостей, в браузере:
  - `config.js` — конфигурация полей, опций, текстов и причин статуса;
  - `storage.js` — работа с `localStorage` (черновик);
  - `validation.js` — проверка обязательных полей;
  - `rules.js` — бизнес-правила квалификации;
  - `card.js` — шаблон карточки заявки и копирование в буфер;
  - `app.js` — состояние, рендер, навигация и обработка событий;
- **Web Storage API (`localStorage`)** — хранение черновика;
- **Clipboard API** — копирование карточки в буфер обмена;
- **Git / GitHub** — управление версиями и публикация.

Проект запускается локально без сборки и зависимости от сервера.

## Запуск

Откройте файл `mvp/index.html` в браузере (двойной клик или `start mvp\index.html`).
Сервер, сборка и внешние зависимости не требуются.

Последовательность заполнения: **Контакты → Объект → Задача → Детали → Проверка → Отправка**.

## Критерии приемки (кратко)

- Анкета состоит из 4 шагов, переход без обязательных полей невозможен;
- каждая обязательная ошибка отображается и объясняется;
- применяется ровно один из трёх статусов с фиксированными причинами;
- карточка менеджера соответствует шаблону из ТЗ;
- статус и причины не показываются клиенту;
- черновик сохраняется и восстанавливается; после отправки удаляется.
